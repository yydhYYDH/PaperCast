# Paper2Video：让论文自动"长出"一场学术演讲视频

> 一篇论文 + 一张作者照片 + 一段 10 秒音频，输出一段可直接使用的演讲视频。这是新加坡国立大学 Show Lab 在 arXiv:2510.05096 中提出的 **Paper2Video**（论文）与 **PaperTalker**（智能体框架）。该工作已被 NeurIPS 2025 的 Scaling Environments for Agents Workshop（SEA）接收。

## 一、问题：学术演讲视频的"高成本"与"高门槛"

学术演讲视频已经成为研究成果传播的主要媒介之一，但制作成本长期被低估。论文摘要指出：为了一段 2～10 分钟的视频，作者往往要投入数小时的幻灯片设计、录制与剪辑。

与自然视频生成不同，学术演讲视频的生成有其独特难点：

- **输入是非结构化的长文档**：直接来源是论文，画面中必然包含大量文字、图与表；
- **需要多通道协同**：幻灯片、字幕、语音、演讲者人像必须对齐（aligned），任一通道错位都会破坏观看体验；
- **没有现成的评价方式**：FVD、IS、CLIP 相似度等视频合成指标衡量的是视觉保真度，而非"是否讲清楚了研究"。

## 二、两项产物：一个基准 + 一个智能体框架

该工作的贡献可以拆成"怎么评"和"怎么做"两条线。

### 2.1 Paper2Video：论文—视频成对基准

Paper2Video 是作者团队提出的基准，包含 **101 篇研究论文**，每篇都配有**作者本人录制的演讲视频、幻灯片以及演讲者元数据**，用于评估面向学术演讲的生成质量，也被作者表述为评测长时程智能体任务的基础设施。

### 2.2 四项定制评价指标

作者认为，学术演讲视频的价值不在于视觉保真，而在于"传播研究"与"放大作者可见度"，因此设计了四个指标：

| 指标 | 面向 | 核心问题 | 实现方式（论文描述） |
| --- | --- | --- | --- |
| Meta Similarity | 观众 | 生成结果有多接近作者原版？ | 幻灯片图像与字幕成对送入 VLM 打相似度分；语音则用说话人嵌入计算余弦相似度 |
| PresentArena | 观众 | 哪一段视频更好？ | 以 VideoLLM 作为"代理观众"做两两比较，胜负率作为指标 |
| PresentQuiz | 观众 | 视频是否传达了论文知识？ | 由论文生成四选一问题，让 VideoLLM 看完视频作答，统计准确率 |
| IP Memory | 作者 | 观众看完能否记住这项工作和作者？ | 受真实会议交流场景启发，衡量观众对作品与作者的回忆关联 |

其中 PresentArena 采用**双序比较**：同一对视频分别以 $(A,B)$ 与 $(B,A)$ 的顺序各查询一次，再对两次判断取平均，以抑制位置偏差与幻觉。

## 三、PaperTalker：四个 builder 组成的一条流水线

PaperTalker 被作者称为"首个面向学术演讲视频生成的多智能体框架"。为了解耦不同角色、便于扩展，流水线被划分为四个 builder：

### 3.1 Slide builder

不走"选模板再用 VLM 反复编辑"的路线，而是**直接依据论文的 LaTeX 工程生成 Beamer 代码**。选择 Beamer 的理由有三点：LaTeX 的声明式排版会自动安排文本块与图的位置；Beamer 表达紧凑，同样的内容比 XML 类格式更少行数；Beamer 自带学术风格的样式（页码、章节标题、超链接等）。

生成流程为：LLM 产出草稿代码 → 编译并收集诊断信息（错误与警告）→ 用错误信息引导修复。编译警告同时被用作"布局探针"，用来定位那些需要精修的幻灯片。

### 3.2 Tree Search Visual Choice

作者指出一个关键观察：LLM/VLM 对数值型布局参数（字号、边距、图缩放）的微小变化**不敏感**，直接让其调参既不稳定也低效。

因此他们设计了"视觉选择"模块：先由规则化方式构造当前幻灯片的布局变体邻域（纯文字页扫描字号；含图页则先变化图缩放因子，如 $1.25, 0.75, 0.5, 0.25$，再缩小字号），把每个变体渲染成图像，再由 VLM 作为裁判打分并选出最优候选：

$$s^{*} = \arg\max_{s' \in \mathcal{C}} \operatorname{VLM\_Judge}(\text{img}[s'], \text{prompt}_{\text{layout}})$$

该设计把**离散布局搜索与语义推理解耦**，能用较少的时间与 token 稳定解决溢出（overfull）问题。

### 3.3 Subtitle builder

字幕不直接来自论文正文，而是来自幻灯片：将生成的幻灯片栅格化为图像后送入 VLM，产出句级字幕 $T_i^{j}$ 以及对应的**视觉焦点提示（visual-focus prompt）** $P_i^{j}$。这一焦点提示是连接"语音"与"光标"的中间表示，为后续时空对齐铺路。

### 3.4 Cursor builder

真实演讲中，讲解者会用光标引导注意力。作者假设**光标在一句话内保持静止、只在句间移动**，从而把问题简化为"每句话估计一个位置与一个时间区间"：

- **空间对齐**：以视觉焦点提示为查询，借助 UI-TARS 等计算机使用（computer-use）grounding 模型，从截图中回归光标坐标 $(x, y)$；
- **时间对齐**：用 WhisperX 提取词级时间戳，与字幕中的对应句子比对，得到该光标片段的起止时间 $(t_s, t_e)$。

### 3.5 Talker builder

给定字幕、作者肖像与语音样本，用 TTS 合成每页语音：$\widetilde{\mathcal{A}}_i = \operatorname{TTS}(\{T_i^{j}\}_{j=1}^{m_i} \mid \mathcal{A})$；再用 talking-head 模型生成演讲者画面。受"人类也常按页分别录制"的启发，且每张幻灯片之间是硬切换、不要求跨页的时间连续性，作者**按幻灯片切分并行生成**，显著缩短了生成时间，并在论文中报告了 **6× 级别的加速**。

> 补充一个工程事实：仓库在 2025.10.15 的更新中提供了**不含 talking-head 的快速版本**（`pipeline_light.py`），适合不需要数字人出镜的场景；README 给出的最低推荐 GPU 为 48GB 显存的 NVIDIA A6000。

## 四、评测与结论（按作者报告）

作者在 Paper2Video 基准上的结论是：PaperTalker 生成的演讲视频在**忠实度与信息量**上优于现有基线，并据此把工作描述为"迈向自动化、可直接使用的学术视频生成"的实用一步。README 与论文摘要层面明确给出的定性结论包括：

- 与 Veo3 这类端到端视频生成模型相比，后者受限于视频时长与画面内密集文字的清晰度；
- 与 PresentAgent 这类多智能体方案相比，后者常见问题是缺少出镜演讲者、以及幻灯片设计缺陷（如内容溢出、标题或机构信息不准确）。

需要说明的是，**具体数值（各指标分数、token 与成本对比等）未在本仓库 README 中给出**，本演示不引用未经确认的数字；完整数据请以论文原文与项目主页为准。

## 五、局限与值得跟踪的点

- 学术演讲视频的"记忆度（IP Memory）"难以模拟，作者自己也将其描述为开放问题；
- 光标轨迹以句为单位离散化，与人类连续、带手势的指针运动仍有差距；
- 流水线依赖 LaTeX 工程作为输入，对没有 LaTeX 源码的论文覆盖能力尚不明确。
