# 09 · 讲述者人格（voice）风格规范：新智元 / 机器之心

> 目的：给文章生成阶段（M2）的「讲述者人格」维度提供**有据可依**的风格规范。
> 本文只做归纳，不复制原文；每条结论都带 8 篇样本里的计数。

## 1. 语料与方法（可复现）

| 项 | 内容 |
| --- | --- |
| 来源 | 两家媒体的**搜狐号镜像**（原站 `jiqizhixin.com` 已改版为「数据服务」页，不再公开文章；微信公众号不可直接抓） |
| 作者页 | 新智元 `sohu userId=473283`；机器之心 `sohu userId=129720` |
| 样本量 | 各 8 篇（从最近 60 篇里按「论文 / 开源 / 模型 / 会议 / 基准」关键词筛出） |
| 抓取脚本 | `var/tmp/style-research/fetch_sohu.py`（搜狐作者 API → 文章正文） |
| 统计脚本 | `var/tmp/style-research/analyze.py`（标题/结构/人称/数字/结尾的可复现计数） |
| 落盘语料 | `var/tmp/style-research/xin-zhi-yuan/`、`var/tmp/style-research/ji-qi-zhi-xin/` |

**已知局限（写提示词时要记住）**：

1. 镜像站会**丢掉原排版信息**（加粗小标题、字号、配图位置）。样本里「markdown 小标题数 = 0」不代表原文没有小标题，只代表纯文本里看不到；从短行分布看，两家都用**加粗短句当小节标题**。
2. 样本里含少量非论文类稿件（产品发布、融资、访谈），计数时已尽量区分「论文解读稿」与「快讯稿」。
3. 语料日期落在 2026-09 前后，风格会漂移；样本仅 8 篇，不宜当成统计结论，只能当**方向性证据**。

## 2. 新智元（`newsflash`：科技媒体快讯人格）

**一句话画像**：把论文/发布当成一条**有情绪、有画面感的新闻**来写 —— 标题用感叹号造势，正文用短句推进、用提问句分节，技术细节按需展开，结尾往行业影响上外推。

### 2.1 标题
- 中文字数 **11–24，平均 17.2**（比机器之心短约 3 字）。
- **感叹号 7/8**，问号 0/8 —— 情绪靠感叹号，不靠设问。
- 「」引号包裹关键概念 3/8（例：把新模型代号或黑话框起来）。
- 时间/快讯词（刚刚 / 突发 / 爆料 / 重磅）出现在 3/8 的标题里，正文里「刚刚」共 7 次。
- 会议名后缀少数使用（1/8），形式是 `机构+动作｜会议年份`。
- 常见结构：`时间词 + 主体 + 动作 + 感叹句`、`结论前置 + 逗号 + 争议/对手`。

### 2.2 开头
- **固定头部「新智元报道」7/8**，紧跟一段 1–3 句的导语。
- 导语类型（按出现次序）：**结论/事件前置** → 悬念或提问 → 一句行业背景。
- 少见「论文出处」式开头；出处常在文中后段才补。

### 2.3 正文结构
- 篇幅 **1500–5500 中文字**，段落行数 45–155（平均 75 行）。
- **没有 markdown 小标题**；靠**独立成行的短句/提问句**分节（每篇约 10–17 处），例如把「为什么换个人就要重来？」这类问句单独成段当小标题。
- 行长度：≤20 字占 24%，21–60 字占 53%，>60 字占 23% —— **短句节奏是主要风格特征**。
- 章节顺序常见：设问/场景 → 事件与结论 → 逐条展开（常用 `1.` `2.` `3.` 列举）→ 行业外推。

### 2.4 人称与判断强度
- 第一人称「我们」17 次 / 5 篇；**不用「小编」「笔者」**。
- 情绪词集中在标题与转折句：最强(8)、刚刚(7)、彻底(4)、终结/颠覆/叫板/狂飙/炸了(各 1–2)。
- 但正文里「可能」出现 33 次 / 8 篇 —— 即**标题强、正文留余地**。这是它和纯标题党的关键区别。

### 2.5 数字与证据
- 数字密度**低**：数字字符/中文字比 0.000–0.060；百分比 0–21 个（技术型稿件才上百位数）。
- 论文链接：**arXiv 0/8**，github 2/8，无「参考链接」段。
- 数字多来自官方发布/技术报告，少标表格出处。

### 2.6 排版与结尾
- **emoji 0 个**；不用列表符号（列表行总 1 行）。
- 结尾：**「编辑：xxx」署名 8/8**，并有产品/公众号引导（7/8 出现自家产品引导语），最后接平台尾巴。
- 正文最后一段常做**行业级外推**（「正在走向…」「或许正在形成…」）。

## 3. 机器之心（`analyst`：技术解读人格）

**一句话画像**：把论文当**一份技术报告**来讲 —— 出处与结论先摆齐，小节标题是技术性的，方法/实验/消融按论文骨架走，评价克制并明确归属到「作者」，结尾给原文与参考链接。

### 3.1 标题
- 中文字数 **14–26，平均 20.0**。
- 感叹号 2/8、问号 2/8、「」2/8 —— 强标点明显少于新智元。
- **会议/机构前缀常见**：`EMNLP 2026主会｜北大×易鑫AI Lab`、`CoRL 2026重磅开源` 这类「出处＋结论」结构。
- 常用「冒号 + 结论」：`大模型Scaling撞上成本墙：三星提出 TrOPD 新方法`。

### 3.2 开头
- 常见三种：
  1. **事件导语**（「就在刚刚，X 发布…」）——快讯型；
  2. **问题切入**（先给一个反直觉现象，再抛出本文要回答的问题）——解读型；
  3. **元信息三连**（标题 / 文章地址 / 项目地址）直接起头 —— 论文解读型，便于读者直接跳原文。
- 署名头部：`编辑｜冷猫、Panda` 形式，3/8 出现；**没有「机器之心报道」固定头**（0/8）。

### 3.3 正文结构（最有价值的一条）
论文解读稿有**稳定的骨架**（样本里直接可见）：
```text
核心结论 → 问题（现状瓶颈）→ 现状综述：主流方法都在改什么 →
诊断实验：先把问题找出来 → 核心方法 → 实验结果 → 结论与展望 → 作者信息
```
- 小节标题是**技术描述型**（「诊断实验：先把 OPD 问题找出来」「核心方法：基于信任域的 OPD」），不是情绪型。
- 行长度**长**：>60 字占 43%（新智元 23%），最长 300 字；短句节奏弱。
- 段落数 43–89（平均 60）。

### 3.4 人称与归属（关键区别）
- 「我们」26 次 / 4 篇（多为引导读者思考，不是社论口吻）。
- **归属词显著更重**：作者 11 次 / 3 篇、这项研究、论文中、结果显示、局限性、尚未 —— 表达「这是作者的工作与声称」。
- 夸张词极少：彻底(5)、最强(3)、惊人(3)，无「炸了/屠榜/遥遥领先」。

### 3.5 数字与证据
- 数字密度略高于新智元（数字字符/中文字比 0.027–0.069）。
- **有图/表引用规范**：图 1、图 2、表 1（各 2–3 次）；**消融** 3 次 / 2 篇；arXiv 2 篇；github 4 篇；有「参考链接」段 1 篇。
- 论文解读稿会单列**作者信息**（第一作者/通讯作者及单位）。

### 3.6 排版与结尾
- emoji 0 个；列表少量（总 13 行）。
- 结尾三件套：**结语式收束**（把工作放回更大语境）+ 客观局限（仿真与真实的差距之类）+ **原文/参考链接**。
- 6/8 出现「关注」类引导。

## 4. 一页对照

| 维度 | 新智元 `newsflash` | 机器之心 `analyst` |
| --- | --- | --- |
| 标题长度 | 平均 17 字 | 平均 20 字 |
| 强标点 | 感叹号 7/8 | 感叹号 2/8、问号 2/8 |
| 出处前缀 | 少（会议名 1/8） | 多（会议/机构／冒号结论） |
| 开头 | 固定「新智元报道」+ 导语 | 导语 / 问题切入 / 元信息三连 |
| 小节标题 | 情绪化提问短句 | 技术描述型 |
| 句长 | 短句为主（>60 字仅 23%） | 长句为主（>60 字 43%） |
| 归属 | 弱（作者 1 次） | 强（作者 11 次、作者信息段） |
| 证据链 | 数字少、无 arXiv | 图表引用、消融、arXiv/参考链接 |
| 结尾 | 行业外推 + 编辑署名 + 引导 | 结语 + 局限 + 原文链接 |
| 情绪 | 标题强、正文留余地 | 全程克制 |

## 5. 可执行的写作规则（直接进提示词）

### 5.1 `newsflash`（新智元式快讯人格）
1. 标题 ≤24 中文字，**必须包含一个强判断或强结果**，句末用感叹号；不写问号。
2. 标题优先句式：`刚刚/最新 + 主体 + 动作 + 结果`；必要时用「」框住关键概念。
3. 首行固定署名行 `新智元报道`，第二行起写 1–3 句导语：先结论，再悬念。
4. 正文 1500–2500 中文字，**每 2–4 句出现一个 ≤20 字的短句独立成段**，用于节奏与转折。
5. 用**提问句或短断言单独成行**充当小节标题，每篇 6–10 处，不写编号式技术小标题。
6. 情绪词只允许出现在标题、导语、转折句；正文主体不堆形容词。
7. 正文至少保留 2 处「可能 / 仍有待 / 目前尚不清楚」式限定语，避免把作者声称写成行业定论。
8. 数字只采用事实源里的数值，保留原始精度与指标名，不四舍五入、不换算。
9. 不写公式；需要方法细节时用「优化什么、约束什么、为什么有效」的中文直觉表述。
10. 结尾一段做**行业级外推**（这项能力会如何改变产业/研究节奏），随后接署名行。
11. emoji 数量 0（除平台强制外）；不用 markdown 列表符号堆信息。
12. 不出现「小编」「笔者」，统一用第三人称叙述 + 少量「我们」引导读者。
13. 通篇不提「论文链接」也行，但若给出，必须来自事实源。

### 5.2 `analyst`（机器之心式技术解读人格）
1. 标题 16–26 中文字，采用 `出处/前缀：结论` 或 `问题：方法名 + 效果` 结构；感叹号最多 1 个。
2. 若论文有会议/机构信息，标题前缀照实写出（如会议名 + 机构），不夸张、不加「重磅」以外的修饰。
3. 开头三选一：事件导语型 / 反直觉问题切入型 / 元信息三连（标题、论文地址、项目地址）。
4. 正文 2000–4000 中文字，按固定骨架组织：核心结论 → 问题与瓶颈 → 现状综述 → 诊断实验 → 核心方法 → 实验结果 → 结论与展望 → 作者信息。
5. 每个小节标题必须是**技术描述型短句**（名词 + 做了什么），禁止情绪化或提问式标题。
6. 句长偏长，允许 100–200 字长句；但每段只讲一件事，段间有逻辑连接词。
7. 归属要明确：写「作者提出」「论文报告」「结果显示」；推论必须标注为推论，不与原文事实混写。
8. 允许保留公式与符号，用 KaTeX `$...$`；变量首次出现给中文解释。
9. 引用图表一律写「如图 N 所示 / 表 N」，且 N 必须来自事实源的图表清单，不得自造。
10. 有消融或对比实验时单列一小节；报告数值时保留原文精度与 benchmark 名。
11. 数字密度可略高，但每个数字都要能在事实源里找到对应项。
12. 结尾给「结论与展望」（把工作放回更大语境）+ 明确局限 + 原文/参考链接。
13. 不写「炸裂/颠覆/遥遥领先」类词；不使用 emoji。
14. 有作者身份信息时，另起「作者信息」小节写第一作者/通讯作者与单位。

### 5.3 两套人格共用的硬约束（沿用现有反幻觉铁律）
- 只依据 `digest.json` 事实源，不引入外部知识；
- 事实源写「未给出具体数值」的内容，任何人格都不许给数；
- 图表 id 只能取自给定清单；
- 输出格式（JSON / Markdown）按平台体裁要求，不由人格决定。

## 6. 反面清单

**勿模仿新智元的部分**
- 把作者的 claim 升级成行业定论（新智元自身也靠「可能」兜底，别把兜底词删掉）；
- 用未证实的爆料口吻写论文（「内部消息」「独家」）；
- 每段都堆形容词，导致正文失去信息量。

**勿模仿机器之心的部分**
- 直接搬运小节骨架却不填内容（空标题 + 两句话）；
- 长句套长句导致指代不清（>200 字）；
- 把「作者信息」写成没来源的履历渲染。

**两家都别做的**
- 抄用某家媒体的标志性表达、专栏句式或独家术语；本规范只抽象**结构性特征**，落地时以「描述性命名 + 参考锚点」使用，UI 上不要用媒体名当风格标签；
- 在没有事实源支撑时补背景科普段落（机器之心/新智元都会补，但补的内容必须来自论文本身）。

## 7. 在本项目里的用法（已落地）

- **已实现**：`app/styles.py`（`PLATFORMS` / `VOICES`）+ `prompts.article_system()` + `generate.run_article` 的变体循环；
  本文件的两个人格对应 `newsflash`（新智元式快讯）与 `analyst`（机器之心式解读），与 `author` / `peer` / `reviewer` 并列。
- 提示词拼装：`人格片段 + 平台硬约束 + 输出模板 + FACT_RULES`，约束优先级 = 事实源 > 平台硬约束 > 人格语气。
- 调试：`scripts/test_article_variants.py`（只跑 article 阶段，复用已有 digest）。
- **人格不能改校验规则**：无公式、标题计重、字数、标签数由平台决定；人格只影响语气与结构。
- 本规范只覆盖「中文科技媒体」两类人格；`author`（作者自述）与 `peer`（同行拆解）需要各自再取样，不应从本文外推。
