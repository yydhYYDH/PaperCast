## 帖子特点（实读 6 篇正文归纳）

> 读了 6 篇（`POST /api/v1/feeds/detail`，只读，各一次浏览器会话）：
> 龟师傅、棉棉、飞天闪客、Bobabot、The Next Token、花叔。
> 其中**飞天闪客、花叔正文为空**（内容全在 9–20 张长图里），文字只留话题标签 —— 这是爆款的
> 另一种形态：图承载信息，标题负责勾人。其余 4 篇有可分析正文。

**标题：先给「点进来的理由」，不写说明书标题**

| 套路 | 例 |
| --- | --- |
| 第二人称日常场景 | 「你刷短视频时，算法如何"读懂"你的不耐烦」 |
| 一句反常识判断 | 「香农信息论撑不住现代 AI 了」 |
| 强背书 / 强结果 | 「深入解读 Kimi 爆火论文，马斯克都转了！」 |
| 反差联想 | 「DeepSeek 最新论文解读：从 Engram 到博尔赫斯」 |
| 痛点 + 动作承诺 | 「论文读不懂，先让 AI 这样拆」 |

**正文：**

- **开头 1–2 句直接给结论或痛点**，不铺垫背景（龟师傅：「核心难题是…传统算法失败了，因为…」；
  Next Token：「NYU 团队提出：香农信息论已经系统性失效…」）。
- **日常类比**讲抽象方法：把概率模型比作「声轨分离器」、把用户行为拆成「不耐烦的声音 / 感兴趣的声音」。
- **结构化、可扫读**：分点分步、短句、段间空行。极端形态是**整篇可复制的 prompt 模板**
  （棉棉：五步「拆问题→拆方法→拆结果→拆启发」，每步给一段能直接粘贴的提示词）。
- **可操作 / 可迁移**：给方法、给对研究者或企业的启示（Next Token：给「高质量数据」一个操作定义）。
- **结尾留互动钩子**：评论区补充「小秘密」、下期预告、内推/招募（龟师傅结尾直接是招聘广告）。
- **人称**：讲现象用「你」、下判断用「我」，或第三人称「团队提出」。

**形式：** 配图 1–20 张；爆款偏长图/信息图。标签 3–8 个，混话题词（#论文解读 #推荐算法 #AI工具）
与平台活动话题（#小红书科技AMA #howto用AI抢救一切）。

> **落成的风格**：以上特点已固化为内置讲述者人格 **`hook`（爆款拆解）**
> —— `apps/papercast-server/app/styles.py` 的 `VOICES["hook"]`，风格页可选（variant `xhs-hook`）。
> 它只改语气/结构，平台的硬约束（≤1000 字、标题计重 ≤38、标签上限）不归它管。

## 长图拆解：花叔《DeepSeek Engram》20 张

> 2026-09-23 实读。花叔那条是 **20 张 1440×2400 竖长图**，文字标题为空 —— 内容**全排在图里**。
> 这是「长图爆款」的典型形态：帖子 = 一本 20 页的小册子，用户竖滑阅读。
> （飞天闪客那条 `type=video`，正文也为空，内容在视频里，只有一张封面图。）

**内容脉络（20 页）** —— 解读 DeepSeek 论文《Conditional Memory via Scalable Lookup》的 Engram 模块：

| 页 | 内容 |
| --- | --- |
| 1 | 封面大字标题「【梁文锋署名】DeepSeek 再发新论文：75%思考+25%记忆，这是他们算出来的最优解」 |
| 2 | Engram 名字来历（神经科学：Richard Semon 1904 的「记忆痕迹」） |
| 3 | 先说问题：大模型浪费算力「背字典」——用 6 层计算才认出固定实体 |
| 4 | 核心思想：给模型发一本字典（**考试带字典**的类比） |
| 5 | 怎么查：哈希定位 + 歧义处理（「苹果」是水果还是公司？看上下文决定用不用） |
| 6 | **关键发现：U 型缩放定律**（纯 MoE 非最优；约 20–25% 参数给 Engram 最好；给太多反而差） |
| 7 | **插一段：博尔赫斯《博闻强记的富内斯》**——「完美记忆会杀死思考」= U 型曲线左端 |
| 8 | 组块 Chunking（George Miller 1956《神奇的数字 7±2》） |
| 9 | 实验结果：推理提升 > 知识提升（MMLU +3.4、BBH +5.0、ARC +3.7、HumanEval +3.0、MATH +2.4） |
| 10 | 机制分析：偷看每层「在想什么」→ 有 Engram 的模型很早层就想明白，**相当于免费加 7 层深度** |
| 11 | 长上下文也提升（大海捞针；Engram 管「这是谁」，Attention 管「发生了什么」） |
| 12 | 系统设计：**字典放抽屉里**（放 CPU 内存，1000 亿参数只慢 2%） |
| 13 | 门控可视化（引用论文 Figure 7 热力图：四大发明、张仲景、伤寒杂病论…） |
| 14 | 往大了说：从「卷计算」到「查表」，空间换时间 |
| 15 | 结尾回收开头的设问：记忆与思考的平衡 = 75% 计算 + 25% 记忆 + 金句 |
| 16 | 参考资料（GitHub + arXiv 链接） |

**形式特点（长图爆款的要点）：**

- **一页一个要点**，短段落、大量留白，竖屏滑动；一页 = 文章的一小节。
- **一个类比贯穿全篇**：考试带字典 → 学生做卷子 → 读小说认福尔摩斯 → 1+1 不用推理。
- **穿插人文 / 认知科学**（博尔赫斯、Miller、Chunking），把 AI 问题接到更大的知识脉络上。
- **引用论文原图**（架构图 Figure 1、U 型曲线 Figure 3、门控热力图 Figure 7）+ 英文 caption，再给中文解读。
- **第一人称**：「看完之后我挺兴奋的」「这是我最想搞明白的问题」。
- **数字精确**（+3.4 / +5.0 / 2% / 7 层），**结尾给参考资料**。

> **与我们的差异**：PaperCast 默认出的是 7–9 张 3:4 卡片（图为主、字很少），
> 而这类爆款是 **~20 张「文字长图」**（把文章排版成图）。`hook` 口吻已覆盖标题/类比/结构，
> 但「长图排版」属于**出图层**，不是口吻能覆盖的 —— 见下一节。

## 能不能复刻「文字长图」？—— 能（已原型验证）

**结论：能。** 2026-09-23 做了最小原型：用现成的 `ops/shot/render_social_deck.mjs`
+ guizang 模板（`template-editorial-card.html`）的 `.kicker / .h-xl / .body` 三个类，
加一条尺寸覆盖，渲出 3 页 **1440×2400** 的「文字长图」，形态与花叔那条一致（衬线大标题 +
小字 kicker + 2–3 段正文 + 大量留白）。渲染入口本来就**按 `.poster` 节点截图、与尺寸无关**，
所以换画布尺寸不用改渲染器。

原型用的配方（自包含，可复现）：

```html
<!-- 每页一个 section，尺寸用 CSS 覆盖 -->
<style>
  .poster.xhs.long { width: 1440px; height: 2400px; }
  .poster.xhs.long .content { padding: 150px 130px; }
  .poster.xhs.long .h-xl  { font-size: 96px; }
  .poster.xhs.long .body  { font-size: 40px; line-height: 1.75; margin-top: 34px; }
  .poster.xhs.long .kicker{ font-size: 30px; }
</style>
<section class="poster xhs long" id="p01">
  <div class="content stack gap-4">
    <p class="kicker">问题 · 大模型在浪费算力</p>
    <h2 class="h-xl">模型用了 6 层计算，<br>才认出「亚历山大帝」</h2>
    <p class="body">…</p>
  </div>
</section>
```

**但有三个缺口，不是"打开开关就有"：**

1. **源文本不够长。** 我们的小红书稿被平台硬约束卡在 **≤1000 字（约 4 段）**，出不了 20 页。
   要出这种长图，得换/加一个**长源**：现成的有 `reading_note.md`（中文精读笔记，可长）、
   知乎长文变体（2000–4000 字）；更稳的是让 LLM 直接产一份**「长图脚本」**（逐页：
   kicker + 标题 + 2–3 段），像分镜一样。
2. **形式哲学冲突。** guizang 技能的 `references/content-planning.md` 明确写着
   「**不要把全文放图上**，图集是视觉提纲，正文留在 caption」。花叔那种是反过来的
   「全文上图」。所以这是**新增一种形态**，不能套技能的卡片配方（M01–M16 都带密度下限）。
3. **自检要换。** 技能的 `validate-social-deck.mjs`（R1 溢出 / R2 页脚相撞 / R4 最小字号 /
   R5 占位 …）是给**卡片配方**定的，文字页会触发它的密度/占位规则。文字长图应改用
   **我们自己的几何闸门**（`app/modules/poster.py` 的溢出检查，已有）。

**落地步骤（中等工作量，约 1–2 天）：**

1. `app/modules/generate.py`（或新模块）加一个「长图脚本」产物：文章 → LLM 拆成 N 页 JSON。
2. `app/modules/cards_deck.py` 加一个 page kind `prose`（kicker + 标题 + 段落，可选嵌论文原图），
   画布尺寸参数化到 1440×2400。
3. 一个开关（如 `PAPERCAST_XHS_LONGFORM=off|on`，默认关），只在显式开启时替换/追加这套图。
4. 自检走 `poster.py` 的溢出闸门，不走技能 R1–R9。

> 不破坏现状：新增形态 + 开关默认关；现有 7–9 张卡片链路不动。

## 复现命令

```bash
# 只读：一次浏览器会话。别循环/轮询 —— 每次调用都以本账号真访问小红书。
curl -s -m 150 -X POST http://127.0.0.1:18060/api/v1/feeds/search \
  -H 'Content-Type: application/json' \
  -d '{"keyword":"论文解读","filters":{"sort_by":"最多点赞"}}'
# filters 还支持 note_type / publish_time / search_scope / location（见 xiaohongshu/search.go）
```

## 账号安全（重要）

- 搜索/浏览他人**比发布轻，但恰恰最像机器人行为**；本账号有过风控记录
  （见 [`../xhs-account-safety.md`](../xhs-account-safety.md)）。
- 规矩：**只在人主动点的时候调一次**、结果落盘缓存、**绝不接自动轮询**；投递/发布在跑时不要同时搜。
- MCP 侧有访问预算（`XHS_BUDGET_MAX`，默认 30 次会话 / 10 分钟，见 `guard.go`），超限直接 429。
